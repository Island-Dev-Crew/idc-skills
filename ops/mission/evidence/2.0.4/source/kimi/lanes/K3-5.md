## Blind pass log

### Architecture observed

- Bash harness + one embedded python3 program (heredoc on stdin, file list via NUL-separated temp
  file in env). Findings on stdout are display-only; pass/fail counts travel in a **separate
  strictly-validated counts file** (`validate_counts_file`: charset {0-9,space,LF}, exactly one
  LF-terminated record, three canonical no-leading-zero ≤9-digit fields). Anything else → fail closed.
- Inventory: content-first (`find -type f` opens **every** regular file; extension only selects
  grammar; unknown/extensionless → union of HTML+JS+CSS scans). NUL-safe `-print0`/`read -d ''`.
  Symlinks, specials (FIFO/socket/device), unreadable files, traversal errors all fail closed.
- Text/binary classification: first 8192 bytes; text iff no NUL and no C0/C1 control outside
  {tab,LF,VT,FF,CR}; high bytes are text. Binaries get `grep -a` for **absolute-scheme only**
  (`EGRESS_BIN` = `(https?|wss?|ftp):...` + stun/turn); an absolute-scheme hit fails even if waived;
  a URL-free binary fails unless `--allow-binary <glob>`.
- TOCTOU: per-file `read_regular_snapshot` (lstat + O_NOFOLLOW + dev/ino + pre/post-read fingerprint
  + size), single immutable latin-1 string feeds BOTH the authority prepass and the findings pass,
  then a closing re-stat/re-sha256 comparison fails closed on any drift.
- HTML: offset-preserving tag state machine, comment/raw-text resolution in source order, first-wins
  duplicate attributes, exactly-once entity decode with decoded→raw offset map, WHATWG host rules,
  srcdoc recursion (depth ≤8), importmap/speculationrules value scanning, meta refresh, inline
  `on*` handlers → JS, `style` attr → CSS, `data:`/`javascript:` executable payloads recursively
  parsed per sink grammar (base64 executable payloads flagged rather than trusted).
- JS: comment/regex/template lexer with lexical-goal recovery incl. TS declaration tails
  (uncertain → UNCERT → fail closed), U+2028/U+2029 + full Unicode WhiteSpace set normalized,
  escape decoding of literals AND identifier tokens, optional chaining/grouping, bracket forms on
  window/document/globalThis/self/top/parent/navigator/this, tagged-template `fetch\`//h\``,
  createElement/script-type state tracking with tree-wide document-ambiguity prepass.
- CSS: escape decoding with structural-code-point sentinel, bad-string recovery, `@import`,
  `url()`, `image-set()`, unquoted URL tokens, `data:text/css` imports recursive.
- Waiver: `WAIVER = (?:^|[ \t])(?:#|//|/\*)[ \t]*egress-ok(?:[ \t]*\*/)?[ \t]*$` — bounded,
  case-sensitive, **trailing** comment searched on the **raw report line** (`WAIVER.search(body)`),
  with `DECODED_WAIVER_BARRIERS` preventing a waiver from crossing a *decoded* JS/CSS line boundary.
- Advisory boundary stated in SKILL.md §"advisory-leaning": string-concatenation/obfuscation-built
  egress is out of rung-1 scope; rung 2 sealed load is the certificate.

### K3-5-C1 — Multi-candidate attributes: leading `data:`/`blob:` candidate suppresses ALL later external candidates — CONFIRMED (runtime-proven), Medium

- **Root cause** (`scan-egress.sh` L290-296): `external_offsets()` returns `[]` for the *entire*
  value when the normalized string merely *starts with* `data:`/`blob:`. That is correct for a
  single URL, but the same function is used for multi-candidate values
  (`srcset`, `imagesrcset`, `ping` — `allow_multiple=True` at L2719/2943, `setAttribute("srcset")`
  at L2576). The attribute value sits inside `consumed_ranges`, and `literal_network` re-adds only
  offsets `external_offsets` found, so even the top-level absolute-scheme fallback is suppressed.
- **Proof (scanner)**: `evidence/K3-5-c1-srcset/fixture.html` —
  `<img srcset="data:image/gif;base64,... 1x, //H/srcset-leak.png 2x">`, `<a ping="data:text/plain,x //H/ping-leak">`,
  `<link imagesrcset="data:...,... //H/preload.png 2w">` → `scan-egress: PASS`, rc=0
  (`scan.out`). Controls: same srcset without the data-first candidate → rc=1 EGRESS;
  relative-first candidate → caught; blob-first → missed; `setAttribute("srcset", "data:..., //H 2x")`
  → missed (`evidence/K3-5-c4-extra/`).
- **Proof (runtime)**: Chromium with `--force-device-scale-factor=2` fetched
  `http://127.0.0.1:8971/srcset-leak.png` from the exact scanner-green page
  (`evidence/K3-5-c1-srcset/hits.log`). Ping runtime: UNVERIFIED in this harness (headless Chromium
  suppressed `<a ping>` even for the absolute-URL control); scanner miss is confirmed regardless.
- **Boundary crossed**: SKILL.md L24 explicitly claims "every `srcset` candidate [is] caught".
  A first *local* candidate launders later external candidates through rung 1's green gate.
- **Fix direction**: split multi-candidate values into candidates BEFORE the data:/blob: outer-URL
  short-circuit.

### K3-5-C2 — Meta refresh without `url=` (bare `;`-separated target) missed for network-path form — CONFIRMED (runtime-proven), Medium

- **Root cause** (L2726-2735, L2953-2962): meta refresh is only scanned when
  `re.search(r'(?ai)\burl\s*=', content)` matches. WHATWG refresh parsing treats the remainder
  after `time;` as the URL even without `url=`.
- **Proof (scanner)**: `<meta http-equiv="refresh" content="0;//127.0.0.1:8971/meta-bare">` →
  PASS rc=0 (`evidence/K3-5-c2-meta/scan.out`). The `URL=//...` form IS caught (control).
- **Proof (runtime)**: over an HTTP base (from `file:` base `//` inherits `file:` — noted
  precisely), `content="1;//127.0.0.1:8971/meta-bare-netpath"` navigated; listener recorded
  `/meta-bare-netpath` (`hits.log`). Bare absolute `content="1;http://..."` also navigates but is
  caught by the absolute-scheme-anywhere rule; only the network-path form escapes.
- **Boundary crossed**: SKILL.md L28 claims "meta refresh" coverage; a shipped artifact viewed over
  HTTP(S) silently navigates off-origin.

### K3-5-C3 — Binary path launders browser-active markup: UTF-16/UTF-32 (BOM) or single control byte; `--allow-binary` glob greens live egress — CONFIRMED (runtime-proven), Medium

- **Root cause**: (a) classification only inspects the first 8192 bytes and routes
  control/NUL-bearing files to the binary path; (b) the binary path's only content check is
  `grep -a` for `EGRESS_BIN` (absolute schemes + stun/turn, L58) — it cannot see a URL whose bytes
  are NUL-interleaved (UTF-16/32) and never looks for network-path `//` forms at all; (c) any
  `--allow-binary` glob match then prints `WAIVED-BINARY` and exits 0.
- **Proof (scanner)**: UTF-16LE+BOM `.html` carrying
  `<script src="http://127.0.0.1:8971/utf16-leak.js">` → unwaived: fails closed as
  `UNSCANNED(binary)` (good); with `--allow-binary '*.html'` or `'*'` → `WAIVED-BINARY`, PASS rc=0
  (`evidence/K3-5-c3-utf16/`). Variant: pure-ASCII `.html` with one 0x01 byte and
  `<script src="//127.0.0.1:8971/netpath-binary.js">` → same green under waiver
  (`evidence/K3-5-c3b-binbyte/`).
- **Proof (runtime)**: Chromium fetched `/utf16-leak.js` from the UTF-16 page and
  `/netpath-binary.js` from the control-byte page served over HTTP (`hits.log` in both dirs).
- **Boundary crossed**: header contract "an embedded URL is reported and fails EVEN IF the binary
  is glob-waived" is false for 16/32-bit encodings and for network-path spellings. The deliberate
  human waiver is the required gating act — but the human is told the grep content-check still
  applies, and it does not.
- **Fix direction**: before honoring a binary waiver, re-check candidate text-like binaries under
  UTF-16/32 decodings and add a network-path pattern to the binary scan.

### K3-5-C4 — Markup-injection sinks unmodeled: `innerHTML` / `outerHTML` / `insertAdjacentHTML` / `document.write(.writeLn)` — CONFIRMED (runtime-proven), Medium

- **Root cause**: the JS grammar scanner models fetching properties (`src/href/...`), DOM setters,
  and navigation APIs, but no sink whose *string argument is parsed as HTML*. A network-path
  `//H` inside those strings is never URL-checked (absolute forms still hit the anywhere-rule).
- **Proof (scanner)**: `document.write('<img src="//127.0.0.1:8971/docwrite-leak.png">')` and
  `el.innerHTML = '<img src="//127.0.0.1:8971/innerhtml-leak.png">'` → PASS rc=0
  (`evidence/K3-5-c4-domwrite/`).
- **Proof (runtime)**: both fetched over HTTP (`hits.log`).
- **Boundary crossed**: SKILL.md's fetching-sink enumeration does not claim these, so this is at
  the edge of the documented boundary — but they are first-class HTML-parsing sinks and the miss
  is silent (no UNCERT). ≤1 layer, no authority crossing; Medium within advisory rung.

### K3-5-C5 — CSS `-webkit-image-set()` string candidates never scanned — CONFIRMED (runtime-proven), Low

- **Root cause** (L2594-2597): `calls` regex `(?<![-_A-Za-z0-9...])(url|image-set|image)\s*\(` —
  the `-` in the lookbehind (added so `not-image-set` stays inert, fixture R9 line 1102) also
  excludes the real fetching function `-webkit-image-set`. Quoted candidates inside it are plain
  CSS literals to the scanner, so network-path strings are missed (absolute forms caught by the
  anywhere-rule).
- **Proof**: `background-image: -webkit-image-set("//127.0.0.1:8971/webkit-imageset.png" 1x)` → not
  flagged while `image-set(...)` control on the next line is EGRESS; Chromium fetched
  `/webkit-imageset.png` (`evidence/K3-5-c5-webkit/`). Blink and WebKit both honor the prefixed
  alias.
- **Fix direction**: match an optional `-webkit-` prefix explicitly for `image-set` (keeping
  `not-image-set` inert via a negative lookbehind for `t-`).

### K3-5-C6 — `<?xml-stylesheet href="...">` PI invisible in `.xml`/`.svg`/`.xhtml` — CONFIRMED (runtime-proven), Low

- **Root cause**: TAGSPAN requires `<` + ASCII alpha; processing instructions are never tokenized.
  `href="//H/x.css"` in an xml-stylesheet PI is a real fetch in browsers for XML documents; the
  network-path form escapes (absolute caught anywhere).
- **Proof**: `evidence/K3-5-c6-xmlstylesheet/` — scanner PASS rc=0; Chromium (page served over
  HTTP) fetched `/xslp.css`.
- **Boundary**: `.xml` is explicitly in HTML_SUFFIXES, so XML grammar is in-scope; PIs are a
  genuine gap in that grammar.

### K3-5-C7 — Waiver authority is self-service and can silence the scanner's own fail-closed UNCERT tripwire — CONFIRMED (scanner), Medium (authority)

- **Findings**:
  1. `egress-ok` remains an **inline, artifact-local, unsigned** comment (`WAIVER` L191). Nothing
     binds waivers to the signed manifest / `integrity/policy.json` — that machinery
     (`skill_integrity.py`, `external_reference_set`) governs the repo's own skills, not artifacts
     scanned by this tool. The 2.0.1-era self-service waiver is **NOT closed**; it is only
     *bounded* (trailing, same raw report line, case-sensitive, decoded-line barriers).
  2. **UNCERT is waivable** (`evidence/K3-5-c7-waiver/u2.ts`): an ambiguous TypeScript lexical-goal
     tail produces `UNCERT ... /re/.test(s)` (the scanner's deliberate "cannot decide, fail
     closed"); appending `// egress-ok` turns it into `WAIVED`, rc=0. A fail-closed tripwire that
     exists *because the scanner cannot prove grammar* can be dismissed by the artifact author.
  3. **One marker waives every finding on the line** (`c6b/w.html` line 2): an `<img src="//H/w3">`
     and a `fetch("//H/w4")` were both WAIVED by a single trailing `// egress-ok` — a reviewer
     approving one URL silently approves the other.
  4. **Waiver text inside an unterminated string literal authorizes** (`c10/w.js`):
     `const u = "https://H/w8-instr // egress-ok` → WAIVED. The WAIVER regex is searched on the raw
     report line, not the grammar mask, so string *content* that merely looks like a comment works.
     (Low practical impact: the author can always write a real comment; recorded for grammar
     precision.)
  5. Wrong-line borrowing is correctly denied (waiver on the next line does not authorize), and a
     non-trailing waiver (`# egress-ok <img ...>`) is correctly denied.
- **Boundary crossed**: the waiver is the *only* human-authority channel in rung 1; items 2-3
  weaken its binding to exactly one reviewed finding.

### K3-5-C8 — FALSE-POSITIVE cluster (pressure toward unsafe waivers) — FALSE-POSITIVE, Info/Low

All in `c7/fp.html` / `adj5/eof.html`, each reported EGRESS though no browser fetch occurs:
1. Absolute URL inside an HTML comment (`<!-- see https://example.com/spec -->`) — documented
   "conservative anywhere in source" policy, but it trains reviewers to waive prose.
2. `<script type="text/plain" src="//H/never-fetched.js">` — browsers never fetch the `src` of a
   data-block script; scanner flags it (add_value_hits runs even when `script_kind == "data"`).
3. Non-fetching attributes (`title="https://..."`) flagged by the anywhere-rule (documented).
4. EOF-unterminated tag (`<script src="//H/x.js"` with no `>`) — browsers discard the tag; scanner
   scans through EOF and flags.
5. **Docs/implementation mismatch**: SKILL.md L76 promises a waiver "with a stated reason", but
   `WAIVER` requires `egress-ok` to be the last token — `# egress-ok reviewed 2026-08` does NOT
   waive (proven, `c6/w.html` line 1). Likewise an HTML-comment waiver `<!-- egress-ok -->` is not
   an accepted delimiter at all. Reviewers following the SKILL.md sentence will believe they waived
   when they did not (fail-closed, safe direction) or will strip the reason to make it work
   (losing the rationale the doc demands).
