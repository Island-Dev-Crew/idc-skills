## Candidates

### K3-4-C1 — Redirection glued to the decisive token (or mid-invocation) silently defeats every guarded subcommand — CONFIRMED — Medium

- **Claim boundary**: SKILL.md claims "The lexical claim is POSIX shell plus the named Bash assignment forms" and header claims redirection handling — but only *leading* forms are modeled (`>/x git push`, `2>&1 git push`, `>|x …`). A redirection operator is POSIX shell grammar anywhere in a simple command; the exclusion list never mentions trailing/mid-command redirections. Gap inside claimed lexical grammar.
- **Mechanism**: shlex is configured with `punctuation_chars=";&|"`, so `<`/`>` glued to a word stay inside the token. `git push>/dev/null` yields subcommand token `"push>/dev/null"` ≠ `"push"`; `git reset --hard>/dev/null` defeats `has_long_opt` (opt `"hard>/dev/null"` is not a prefix of `"hard"`); `git restore .>/dev/null` makes the operand non-whole-tree. Short-flag bundles are unaffected (`-fd>/dev/null` still yields flags f,d → still blocked — the bypass needs the redir on the *decisive* token).
- **Guard results (exit 0 = allowed)**: `git push>/dev/null`, `git push</dev/null origin main`, `git</dev/null push`, `git reset --hard>/dev/null`, `git restore .>/dev/null`, `git checkout .>x`, `git clean --force>/dev/null -d`, `git switch --discard-changes>/dev/null main`, `git branch --force>/dev/null b1`, `git push>/dev/null 2>&1` — all **0**.
- **Real-git proofs (disposable lab /tmp/K3-4/lab, bare remote)**: push variants moved the remote ref (`c474a5d7→c371637e`, and earlier `aeb3a66→5226881→56f37f5→f69a537` across three variants); `reset --hard>/dev/null` restored a destroyed README; `restore .>/dev/null` and `checkout .>x` discarded whole-tree edits ("Updated 2 paths from the index"); `clean --force>/dev/null -d` deleted untracked files; `branch --force>/dev/null keep HEAD` moved a branch ref (`5226881a→f69a5371`); `switch --discard-changes>/dev/null main` discarded edits.
- **Reachability**: trivial; no quoting/exotic state needed — plausible even as accidental agent output-suppression style. Adjacent layers: Layer-1 denylist regex `git\s+push\s+.*--force` also misses all these forms (no `--force` text), so no layer below catches it within this skill. Severity Medium: defeats the flagship `push` authority gate inside the claimed POSIX lexical grammar; mitigated by the guard's documented advisory nature.
- **Fix direction**: treat `<`/`>` (and `>&`/`<&`/`>|`) as token boundaries everywhere, not only at segment head, and strip trailing redirection tokens from the git slice.
- Evidence: `evidence/K3-4-redir/proofs.txt`.

### K3-4-C2 — `-c clean.requireForce=false clean -d` deletes untracked files with no force flag — CONFIRMED — Low

- **Claim boundary**: the runtime-config model is explicitly scoped to `alias.*` keys; non-alias config that changes subcommand danger semantics was never claimed. But Layer 2's stated authority gate is "`clean -f[d]`" i.e. destructive clean; this bypass defeats the gate's intent with one global option the classifier otherwise fully parses.
- **Guard**: `git -c clean.requireForce=false clean -d` → **0** (also `clean` alone, and the env/PARAMETERS equivalents, since only alias keys are inspected).
- **Real-git proof**: removed `gone1.txt`/`gone2.txt` ("Removing gone1.txt …"). Real git precedence verified consistent (last `-c` wins), so a forced override cannot be laundered the other way.
- **Severity Low** (boundary miss, trivially reachable; recoverability is via no path — clean deletion is irreversible, but it only hits untracked files, and Layer 1 deliberately allows `git clean -fdx` outright anyway, so the fleet-wide posture already treats clean as recoverable-class).
- Evidence: `evidence/K3-4-cleanreqforce/proofs.txt`.

### K3-4-C3 — Bang alias `!git` (inert body) composes with call-site args: `git -c alias.p='!git' p push` — CONFIRMED — Medium

- **Claim boundary**: header claims "alias values that only become dangerous once COMBINED with call-site args (`-c alias.n=reset n --hard`)" are caught — true for *normal* aliases (call-site args retained in expansion) but **not for `!`-aliases**: `git_invocation_danger` step 2 classifies only the bang body (`classify("git")` → inert), discarding `git_slice[idx+1:]` even though real git appends call-site argv to the shell command. Claimed-covered class fails.
- **Guard**: `git -c alias.p="!git" p push` / `… p reset --hard` / `… p clean -fd` → all **0**; also via inherited `GIT_CONFIG_PARAMETERS` in git-native `'alias.p'='!git'` encoding → **0**.
- **Real-git proofs**: `p push` moved remote (`c371637e→dfbb9e51`; and `dfbb9e5→3b59046e` via PARAMETERS encoding); `p reset --hard` restored destroyed README; `p clean -fd` deleted untracked files. `p status` confirmed arg-append semantics.
- **Severity Medium** (defeats push gate inside the claimed alias-composition grammar; reachable via `-c`, `--config-env`, COUNT, and PARAMETERS channels).
- **Fix direction**: when the invoked alias value starts with `!`, classify `body + shell-quoted(call-site args)` (or conservatively flag any invoked bang alias whose body ends with a bare `git` word).
- Evidence: `evidence/K3-4-bangargs/proofs.txt`.

### K3-4-C5 — Plumbing ref rewrites unguarded: `update-ref` move/delete, `tag -f` clobber — CONFIRMED (execution) — Low

- SKILL.md claims "forced branch/ref moves" while the header concretely scopes that to `branch -f/-M/-C`. `git update-ref refs/heads/x <sha>` is an unconditional forced ref move and `update-ref -d` a ref deletion; `git tag -f` clobbers a tag ref.
- Guard: all **0**. Real-git: `update-ref` moved `x` (`3b59046e→c474a5d7`), `update-ref -d x` deleted it, `tag -f v9 HEAD~1` re-pointed the tag.
- Low: claim text is ambiguous ("ref moves" could cover this → would justify Med); plumbing commands are less likely agent output, but they are the standard scripted-history-rewrite tool. Adjacent: `git replace`, `git filter-branch`/`filter-repo` same class.
- Evidence: `evidence/K3-4-updateref/proofs.txt`.

## Attempts (attack classes exercised and correctly CLOSED — guard verdict matches real git semantics)

- IFS/quote-splice: `git${IFS}push`, `git $IFS push`, `git${IFS:0:1}push`, `'git' push`, `g'it' push`, `gi"t" push`, `g\it push`, `git "pu"sh` → all block. (`g'it push` allow is correct — unbalanced quote, real bash syntax-errors.)
- Wrappers/paths: `command git push` (block), `command -pv git` (allow — query, correct), `env -S 'git push'` / `env -iS 'git push'` (block), `env -S 'GIT_CONFIG_PARAMETERS=… git p'` (block), `sudo -u root git push` / `sudo GIT_CONFIG_PARAMETERS=… git p` (block), `/usr/bin/git push`, `./git push`, `git.exe push`, `! git push`, `{ git push; }`, `if true; then git push; fi`, `case x in x) git push;; esac` (all block).
- Leading grammar: `> /tmp/x git push`, `2>&1 git push`, `VAR+=x git push`, `A[0]=x git push` → block.
- Separators: `;`, newline, `&&`-carried state, `|&`, subshell `(...)` → block; comments respected.
- Alias/env injection: `-c alias.p=push p`, glued `-c`, nested `-c alias.n='-c alias.p=push p' n`, `alias.n=reset n --hard` (block) vs bare `n` (allow, correct), `-c alias.p='!git push' p`, `git config alias.x push` / `'!git push'`, case-folded `ALIAS.`/`Alias.`, inherited `GIT_CONFIG_PARAMETERS` (git-native `'k'='v'` and `''\!` bang-escaped encodings parsed), COUNT+KEY/VALUE env, call-site composition for normal aliases → all block/allow as claimed. Defining a dangerous alias blocks even uninvoked (documented conservative).
- Precedence: verified against real git — `-c` beats `GIT_CONFIG_PARAMETERS` beats COUNT, last duplicate wins, `--config-env` argv order honored; guard verdicts matched real git on both orderings. Malformed/missing `--config-env`/COUNT entries block (fail-closed as documented).
- Global options: `-C`, `--git-dir=`/`--git-dir <sp>`, `--work-tree=`, `--no-pager`, `-c k=v` → subcommand still found. Real git 2.39.5 **rejects** abbreviated global options outright (`git --git-di /x push` → "unknown option"), so the documented separate-form-abbreviation residual is not exploitable on this git.
- Pathspecs: `.`, `./`, `./.`, `:/`, `:/:`, `*`, `?*`, `[a-z]*`, `:(top)`, `:(top,glob)**`, exclude magic (`:!x`, `:^x`, `:(exclude)x`, `:(top,exclude)x`), `--pathspec-from-file(-)`/`--pathspec-file-nul` → block; `:(literal)` wildcard-named files and concrete subtree `sub/` → allow (intentional).
- reset/clean/branch/checkout/switch forms: `--ha`/`--har` abbrevs, bundled `-fb`/`-fq`, `-df`/`-fd`, `-D`, `-M`/`-C`, `--dele --forc`, `-e`/`-b`/`-c`/`-s` arg-consumption of `--` keeping later live options visible, `restore -SW`/`-WS`, `switch --discard-changes`/-C → all blocked; dry-run clean allowed.
- Heredoc body line → block (documented over-block). `python3 -c "alias.p=push"`, `echo git push`, commit messages → allow.
- Real-git consistency spot-checks: `git reset -hard` (git itself rejects → allow correct); `git reset --keep/--merge` refuse to lose uncommitted data; `git restore --worktree --staged` without pathspec is a no-op.
