04 · Threat model

The dangerous path is not a poisoned file alone. It is trust multiplied by authority.

The transcript's secondary account was cross-checked against primary public disclosures from Zenity, AIR, and OWASP. The resulting control target is a chain, not a buzzword.

01 · TrustLegitimate local skill

The agent loads a skill that passed an earlier inspection.

02 · PointerMutable remote page

The signed local bytes direct the agent to external instructions.

03 · FlipRemote content changes

The page becomes hostile after scan time without changing the local skill.

04 · ExecuteFetch-and-run path

New instructions trigger code or package execution.

05 · ImpactAgent authority abused

Credentials, repositories, cloud access, and child agents expand the blast radius.

Design consequence: byte signing alone is necessary but insufficient. The signed object must also enumerate every external reference and network-command occurrence, distinguish attribution/API endpoints/runtime instructions, pin mutable runtime content, and deny fetch-and-execute shapes unless an exact reviewed exception is itself signed.
05 · Integrity architecture

One external key. One canonical manifest. Five checks that fail independently.

Every regular file beneath all fifty skill directories is inventoried. Symlinks, non-regular entries, collisions, count drift, new references, unexpected network commands, wide encodings, and signed control-plane drift are explicit failures.

Signature & anchor

Verify the detached Ed25519 signature, public key, allowed-signers entry, namespace, principal, and fixed fingerprint.

FAIL: wrong key, signature, namespace, principal, or anchor

Local & control bytes

Recompute exactly fifty skill trees, every regular byte, inventory shape, policy, verifier, installer, hook, workflow, tests, reports, and other fixed controls.

FAIL: tamper, addition, deletion, link, encoding, collision, or control drift

Reference policy

Re-scan every HTTP(S) occurrence and network-command occurrence against signed classifications and exceptions.

FAIL: new URL, command, denied pattern, or policy mismatch

Remote immutable pins

Re-fetch only references classified as runtime instructions, validate HTTPS, final URL, and content SHA-256.

FAIL: drift, redirect drift, transport or pin mismatch

Fetch/execute policy

Deny pipe-to-interpreter, process substitution, dynamic fetch/eval, download-to-file, and network package execution unless an exact reviewed exception is signed.

FAIL: denied pattern or exact exception mismatch

The private key remains in 1Password. Signing uses the system OpenSSH client and requires operator approval. The release CLI has no user-selectable fingerprint override.

Installed path

Verify before write; bind what runs

The release CLI verifies by default with no command-line opt-out before install or export mutation. Installs compare source/staged/installed maps; exports build only from a staged source snapshot bound to the authenticated map. The pre-tool hook requires the actual installed-skills root, rejects explicit-skill/payload disagreement, and returns blocking exit 2 on every unexpected exception.

06 · Adversarial review

The gauntlet found a genuine false green—and the release was stopped until it died.

The first attack lane generated its own key, replaced the repository public artifacts, supplied a CLI fingerprint override, and obtained 5/5 without the Forge key. That was a release-blocking defect, not a documentation concern.

HIGH · FALSE GREEN

User-selectable trust anchor

An attacker-controlled fingerprint could make an attacker key authoritative to the CLI.

Closed: override removed; release verification requires the compiled constant; attacker-key fixture must fail.

MEDIUM · INTEGRATION

Optional installed-tree binding

The hook could verify pristine canonical bytes while a different installed copy executed.

Closed: installed-skills path is mandatory and its bytes must match the manifest.

MEDIUM · PARSER

Wide-encoding scan bypass

UTF-16/32 could hide denied command text from a permissive UTF-8 decoder.

Closed: skill text must be strict UTF-8; NUL-bearing and wide-encoded content fails closed.

MEDIUM · PATH

Control path escape

A signed policy could point a control entry outside the repository root.

Closed: absolute, dot-dot, symlinked, missing, and resolved-outside paths are rejected.

MEDIUM · TEMPORAL

Live-tree change after first hash

A writer could replace a skill after its first read but before the verifier returned, leaving the observed snapshot green while the path was poisoned.

Closed within the observable run: the complete local manifest is recaptured immediately before authorization, and installed skill directories are captured twice. Post-final-read mutation remains an OS-containment boundary.

LOW · CI SEMANTICS

Fixture mode returned success

A generic wrapper could confuse non-authorizing fixture success with release authority.

Closed: fixture controls are internal test APIs, absent from the release CLI, and cannot produce readyToRun.

LOW · RELEASE POLICY

Fixture transport escape available to a release signer

A future signed release policy could have deliberately admitted HTTP for a runtime instruction through the fixture-only escape.

Closed after cross-family review: release runtime instructions require HTTPS for source and final URL and reject the fixture escape key.

LOW · WINDOWS PATH

No native O_NOFOLLOW guarantee

Windows cannot rely on the POSIX no-follow open flag, leaving a narrow check/open replacement window.

Closed after cross-family review: trusted-file capture compares the pre-open path device/inode identity to the opened descriptor in addition to using O_NOFOLLOW where available.

MEDIUM · SECURE DEFAULT

Direct installer skipped verification

The Python entrypoint installed unsigned bytes unless the caller remembered --verify-integrity, contradicting the release installer contract.

Closed after exact-head review: verification is default-on, the release CLI exposes no opt-out, and an unflagged red-gate test proves no target write occurs.

LOW · HOOK FAIL-CLOSED

Unexpected adapter exception could exit 1

An unanticipated hook exception could produce a harness-nonblocking exit and lacked red regression coverage.

Closed: all unexpected exceptions collapse to exit 2 without leaking exception text; tests cover red gate, exact-byte green, unknown skill, installed drift, and exception behavior.

HIGH · EXPORT AUTHORITY

Red repository could still emit bundles

Both Claude.ai export modes transformed and packaged source bytes without first requiring the signed gate.

Closed: install and export direct APIs default to verification, release CLI has no opt-out, selected skills are copied to scratch, and only a staged snapshot matching the authenticated file map can become a bundle.

HIGH · IDENTITY BINDING

Fixed hook skill could mask payload skill

A configured --skill value took precedence over a conflicting skill identity in the live hook payload.

Closed: when both identities are present they must match exactly; mismatch returns blocking exit 2, and all hook verdict text is ASCII-safe across Windows/OEM streams.

MEDIUM · WINDOWS DETERMINISM

Renderer emitted platform-native newlines

The first PR #3 Windows run regenerated the validation report with CRLF bytes, then correctly rejected it against the canonical LF artifact.

Closed: the renderer explicitly writes LF bytes on every platform, and a Windows-sensitive regression compares the generated bytes to the committed report.

LOW · RELEASE LINT

Four shell idioms failed the CI lint bar

The first Ubuntu run rejected one redundant pipeline, two ambiguous && … || chains, and an optional prompt called without an explicit argument.

Closed without changing outcomes: direct input, explicit fail-closed conditionals, and an explicit prompt now pass the exact shellcheck surface used by CI.

DESIGN BOUNDARY

Repository cannot attest itself

A same-user attacker may replace both verifier and repository files before invocation.

Not hidden: trusted launch must pin the verifier and key fingerprint outside this repository.

09 · Honest residuals

What 2.0.2 still cannot honestly claim.

These are not footnotes to be erased by a signature. They define the boundary of the assurance case.

High

Trusted bootstrap

The consumer must verify the public-key fingerprint and trusted launcher out of band. Repository code cannot prove its own authorship.

High

Runtime containment

The gate does not sandbox the agent, revoke credentials, block every obfuscation, or stop same-user post-check tampering.

Medium

ICM history gap

The live head and MIT license are recorded, but the exact historical fusion commit remains unknown and is not silently replaced.

Medium

Multi-target rollback

Each destination replacement is atomic and reversible; a whole multi-target operation is not globally transactional after unexpected I/O failure.

Product limit

claude.ai export

The current pack remains fail-closed: 48 descriptions exceed the observed limit and 13 explicit-only semantics lack proved equivalents.

Evidence gap

Video frames

The first source video could not be retrieved. Transcript analysis is usable; the requested visual channel remains unverified.
