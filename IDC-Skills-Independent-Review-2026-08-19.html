03 · Confirmed findings

Where the evidence breaks

Each serious finding was replayed from a second angle. None depends on a green exit code alone.

High · F-01
Authority guard

The shipped “all variants” git-push guard has safe-to-demonstrate bypasses

The skill promises that Layer 2 blocks git push in all forms. Its regex only matches git immediately followed by whitespace and push. Git global options inserted between them evade the hook.

Probe: plain git push origin main returned 2 (blocked); the inert JSON payloads git -C /tmp push origin main and git --no-pager push origin main both returned 0. No git command was executed—the hook only classified strings.
Closure: parse the git command form (including global options) or match the complete invocation grammar; add negative fixtures for -C, -c, --git-dir, --work-tree, and global long options. State this as advisory until a wired hook and bypass suite are green. The inspected Claude settings do not currently wire this bundled hook, so this is a shipped implementation defect—not evidence of a live intercepted command.
High · F-02
Evidence integrity

The “every island’s validation record” report covers only 40 of 50

README.md describes docs/report.html as every island’s validation record. The embedded dataset contains 40 skills and 120 cases.

Missing: ai-humanizer, batch-sample-curate, computer-use-smoke, connected-fix-prompt, delegated-authority-prompt, exposure-audit, model-routing, self-contained-ship, skill-duel, and skill-supply-chain-review.
Closure: commit machine-readable per-skill case records for all 50, generate the HTML from them, and make reacceptance fail unless report names equal registry names. Until then, the 50/50 structural gate is green but the 50/50 semantic evidence claim is not.
Medium · F-03
Provenance

The fusion narrative is rich; the provenance lock is not reproducible

The registry stores descriptive lineage but not upstream URL, exact upstream commit, archive digest, license, or copied-notice mapping. The repository’s root MIT notice names IDC only.

Recovered outside the repo: local source archives identify David Ondrej commit 6e554508… (45 skills, archive SHA-256 4435827e…) and Matt Pocock commit 2ab95809… (41 skills, archive SHA-256 8b236fd3…). Their MIT notices are present inside the zips. The two local fusion-report files are byte-identical. No exact historical ICM source pin was found.
Closure: add a tracked provenance lock with source URL, source commit, archive hash, license, notice path, affected skills, and transformation record. Preserve upstream notices. This is a reproducibility and compliance-evidence gap; it is not a legal conclusion.
Medium · F-04
Composition

Several model-invoked skills silently route to explicit-only skills

The suite’s own authoring canon says a user-invoked target cannot be autonomously fired and the body must tell the human to invoke it. That invariant is not enforced by the validator.

Examples: spec-pipeline says to run user-only wayfinder; research routes to user-only teach; video-analysis pairs with user-only wait-what; ai-humanizer hands work to user-only prose-craft/short. None includes the explicit human-invocation instruction that the conforming grill → to-questionnaire route demonstrates.
Closure: repair the four bodies and add a semantic reachability fixture covering registry invocation policy, markdown targets, and the required “tell the human” language for explicit-only destinations.
