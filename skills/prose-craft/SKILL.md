# Prose Craft: explore then exploit

Author one original piece of human-facing prose. The concern is the whole arc: widen the material, then commit to a shape. Two phases, never blurred. **Explore** widens without structuring; **exploit** structures without widening. This skill is **advisory throughout**: it enforces nothing, blocks nothing; every rule below is a discipline you keep, not a gate that stops you.

Work in files. Ask once where the fragment file and the article file live, then remember both for the session. Before every write, re-read the target file from disk, since the user may have edited, reordered, or cut between turns. Append; never overwrite blindly. Edit a specific fragment or beat in place only when asked.

## Phase 1: EXPLORE (mine fragments, coin the leading word)

Pure widening. No outline, no phases, no article structure yet, because imposing shape is exploit's job. Interview the user relentlessly and append fragments to one markdown file as they surface from either side, from the first thing said. First write: a single H1 working title, nothing else (no metadata, no TOC, no date). Separate fragments by a horizontal rule (`\n---\n`); no headings inside the body.

A **fragment** is any text that might survive into the final piece. The bar is *is this good writing?*, not *is this a self-contained argument?* It must be readable by the author, not by a cold reader. Fragments are deliberately heterogeneous: a sharp sentence with no home yet, a claim plus one-line justification, a vignette or analogy or code snippet, a half-thought to finish later, a quote, a cluster of observations that hang together by feel.

The **leading word** is the fragment worth hunting hardest. It is a compact metaphor or coinage the whole piece hangs on: one term that names the idea the way *tracer bullet* or *fog of war* names a pattern. It is load-bearing: coin the right one here and it shapes the structure, the transitions, and the title through all of exploit. When the conversation circles a recurring idea, push to name it. An existing term the reader already holds beats an invented one, since a made-up word recruits no priors. Reach for a live one first, and if you must coin, define it clearly.

## Phase 2: EXPLOIT (grounded beats, optional block form)

The pile is fixed; the widening is done. Commit to a path through it and mine it to fill each move. The quarry is read-only here: pull, paraphrase, split, recombine, quote; never edit the fragment file. Most piles leave leftovers. The piece ends when the journey is complete, not when the pile is empty.

**Grounding is the gate.** Every **concept** must be grounded before a beat leans on it: the reader walked in knowing it (a **prerequisite**, fixed before the first beat) or an earlier beat **introduced** it. The unit is the concept, not the word: a beat can lose the reader on an idea they lack with no jargon in sight. Where a concept has a name, ground the idea and the term together. Each beat does two jobs. It **requires** only grounded concepts and **grounds** new ones. Keep a running list of what is grounded; update it as each beat lands. The one move the journey cannot make is reaching for an ungrounded concept; the fix is a grounding beat before it, or promoting the concept to a prerequisite. The big lever is what you make prerequisite versus what you ground inside: demand too much up front and you shut readers out; ground too much inside and the opening drowns in definitions. Settle it with the user when you set prerequisites.

Build **beat by beat**, choose-your-own-adventure. Set prerequisites first. Then offer 2 to 3 candidate beats as different entry points, each leaning only on grounded concepts, each noting what it grounds. The user picks; write **only that beat** to the article file, then stop. Re-read from disk, offer 2 to 3 next beats reachable from the current grounded set, and say what each grounds so the user sees which paths it opens. Loop until the piece reaches a natural end. A **beat** is one move (set a scene, land a point, ask a question, twist the angle), sized by what it needs: a single sentence, a short paragraph, or a self-contained vignette. If a beat needs five paragraphs and three subheadings, it is two beats glued together; split it.

Argue **block form** out loud, never silently: prose vs. list (prose carries argument; a list carries truly parallel items), inline vs. callout (a `> [!NOTE]` only when it would derail the main line inline), table vs. bold-led prose (a table when the same shape repeats 3+ times), quote vs. paraphrase (quote when the wording is the point), code block vs. inline. Refuse weak transitions: *what does this beat do that the last one didn't? If I cut it, what breaks?*

## The evidence layer

Simplify the prose, never the evidence. When a beat asserts a fact, mark its truth status honestly: verified (name the source), unverified (say so), or unknown (say you don't know). Never launder an unverified claim into confident prose because the sentence reads better. A polished line carrying a fabricated fact is a defect, not a flourish. State plainly that this skill is advisory: the grounding gate and the form arguments are disciplines the author keeps, not checks any tool enforces.

**No authority without evidence. Polish the sentence, never the fact.**
