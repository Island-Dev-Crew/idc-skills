The Forge

Forty-three agent skills, told as one journey. Each skill is an island; together they take a task from "should we even build this?" all the way to "it is verifiably live." Read it top to bottom, or jump to the act you need.
The first law
No authority without evidence.

A claim is not done until a check that could have failed proves it. The forge says which rules are enforced and which are advice — and never dresses a guess up as a fact.

The second law
The repo is the memory.

State lives in files, not in a chat window. A fresh agent, given only the folder, can pick the work up — because the folder routes it and the tree holds the truth.

Where the eleven come from

Most of these islands are fused from two public canons — David Ondrej's and Matt Pocock's — and from Jake Van Clief's Interpretable Context Methodology. That is why the source repos feel redundant now: the forge absorbed them. But twelve islands are IDC's own. Five exist nowhere else — lane-claim, finding-register, domain-wire, console-as-code, evidence-packet. Seven more ship nowhere else in this welded form — the ICM cluster, where a public methodology is bound to no authority without evidence so the map becomes a contract, not a convenience. Add the review ceremony inside cross-family-review, run in production with receipts. That weld is the product.
